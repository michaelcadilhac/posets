Estimator discipline:
- P = median of three matched optimized/baseline ratios.
- V = optimized variant median / baseline variant median; the displayed ms
  columns are those separate variant medians. P need not equal V.
- Below1 is faster. Do not pair median-ms endpoints with P as its arithmetic.
  Standard collector compatible rebuild is the clearest warning: medians
  .248341 -> .254329ms give V1.0241, but P.8774; ratios .8585/.8774/1.3733.

What the separate work/heap companion should settle before any new patch:
1. Constructor/public-insert rank_of still scans each input on both sides.
   Expect identical constructor rank call/active-coordinate totals. Thus do not
   attribute full-arbiter constructor gains to cached union/intersection ranks.
   PO attempts, actual removed generators, completed relocation moves and
   accepted-insert behavior should distinguish skipped equal-rank eviction and
   avoided full-tail compaction from the changed paired reserve policy.
2. CPre: measure apply, union and intersection separately. Union should avoid
   RHS reranking; intersection stored/copy rank reuse should remove those scans.
   Apply still ranks mapped values and supplies an insertion/control phase.
   Record actual no-op status and first failed query; only observed covered
   intersections justify claiming zero output copies/allocations. Changed
   intersections may still allocate meets and replay the covered prefix.
3. Compare allocation count/requested bytes/extra peak as well as copied/moved
   vectors. New paired reserves can trade capacity/retained bytes for fewer
   reallocations, so fewer allocations is not automatically less memory.
   Constructor-only caller storage is still alive; use normalized build/rebuild
   and whole-CPre lifetimes for retained/net deltas. Private rank capacity is not
   inferred. Per-operation and whole-ROI passes are independent, and contains
   temporary-query lifetimes differ between those two passes as already reviewed.
4. Algorithm-level rank/PO counts should be reconciled across widths on the same
   trace. Equal counts would not imply equal instructions or touched bytes:
   SIMD padding, scan lengths, allocator/layout and generated loops remain
   possible mechanisms, not measured explanations. Instrumentation changes
   code generation and is not a clean timing or cache-miss measurement.
