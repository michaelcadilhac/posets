otf_sparse_formula_parity and empty primary runtime flags. The preset starts
seven competing workers. Changing VECTOR_AND_BITSET_DOWNSET_IMPL changes the
selected downset in solve_game_vector.cc; it does not replace every search
structure in the portfolio.

Worker scope

* real:small:backward uses the selected downset for the backward fixed point
  and its CPre operations. The optional equivariance prepass also receives the
  selected downset type.
* unreal:formula:spot-guarded-sparse uses its own sparse RowStore/Search before
  semantic action/downset construction. The default candidate_mode::only
  returns on an inconclusive candidate rather than falling back to backward.
* unreal:automaton:forward searches with separate node/index structures and
  minimal_losing_antichain. A successful search constructs selected downsets
  for certificate verification; failed certificate verification can fall back
  to the backward solver. It is therefore not a complete downset bypass.
* both:gr1-real-lift:oxidd, both:obligation:spot, both:parity:spot and
  both:parity:oxidd dispatch to their own implementations before run_ltl /
  solve_game, without using the selected downset implementation.

Other bypasses and lifetimes

Before selected-downset construction, the legacy workers can return through
no-input/no-output checks, forced-output contradiction, or Spot's deterministic
NBA fast path. Translation, simplification, preprocessing, action generation
and the independent native solvers are not accelerated merely by changing the
downset. See ANCHOR/src/solver/solver_invoker.cc:620–655, :793–829,
:828–869 and :1126–1141. The first decisive portfolio result cancels competitors,
so speeding a worker that does not decide the case need not reduce wall time.

Within backward CPre, each action calls f.apply to construct a fresh downset;
the action results are combined by union and then intersected with f. In this
measured lazy implementation, a nontrivial intersection constructs a fresh
result and swaps it in. Raising K also applies a transformation to a fresh
result. See ANCHOR/src/solver/k_bounded_safety_aut.hh:229–249 and :259–319,
and INTEGRATION/subprojects/posets/include/posets/downsets/lazy_kdtree_backed.hh:445–470.
This limits the lifetime over which frozen-index construction can be amortized.
It does not imply that lazy index reuse is absent: queries and monotone updates
can reuse an index during its epoch. The forward solver separately documents a
fresh search for each K at forward_k_bounded_safety_aut.hh:23–28.

Evidence limit

These are static dispatch and lifetime facts. The primary campaigns did not
enable route records, phase records or worker recording, and release builds
compile out verbose logging. We cannot infer the fraction of cases reaching
this backend, which worker won each case, or a bottleneck percentage from these
measurements. It is plausible that many results are insensitive to the chosen
downset, but that frequency has not been measured. Separate captured-CPre
comparison-attempt evidence concerns those recorded frames; it is not a route
frequency estimate for the full corpus.
