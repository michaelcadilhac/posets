Add a bounded positive allocation-failure/retry sweep for map queries:

1. Build the forest, query Vector, expected scalar result and a snapshot of its
   generators before the failure scope. Choose a nontrivial query known to visit
   cached nodes; empty/dimension-zero/no-traversal cases cannot prove hook coverage.
2. Warm query stack capacity and map buckets outside the failure scope. A warmed
   covers query still clears map nodes and inserts again in this control.
3. Increase the allocation budget across successive attempts. Limit the charged
   region to covers_vector itself. Catch only the intended bad_alloc, reset the
   budget before any verification, and count failures. Require failures > 0 and a
   successful attempt before the bounded sweep ends; do not accept an all-zero-hook
   or never-completed sweep as coverage.
4. After each failure, query the SAME root again with allocations enabled and check
   strict/non-strict answers against the independent oracle. Check materialized
   generators, count and child ordering outside the failure window. The next query
   must clear partial cache state and remain reusable; no rebuild/reassignment may
   hide corruption between the failing query and retry.
5. Keep all full semantic cases running after this sweep. Do not infer allocation
   semantics from timing, or count oracle/setup/report allocations as query faults.
